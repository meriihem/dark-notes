# Dark Notes 2.0 — технический план

**Ветка:** `dark-notes-v2-mystical-archive`  
**Базовая версия:** `main` (не изменяется)  
**Концепция:** Balanced Mystical Archive  
**Навигация:** Bottom  
**Редактор:** GRIMOIRE

## 1. Зафиксированные продуктовые решения

- Визуальный стиль: сдержанная мистика, премиальный минимализм, чёрный обсидиановый фон, приглушённое золото, тонкие символы и орнаменты.
- Навигация: нижняя панель с разделами «Архив», «Коллекции», «Избранное», «Настройки».
- Редактор: GRIMOIRE — спокойная рабочая область цифровой рукописи, без тяжёлых декоративных рамок.
- Функции версии 2.0: коллекции/папки, теги, чек-листы, изображения, экспорт/резервные копии, биометрическая блокировка, календарь/хроника, напоминания.

## 2. Принципы безопасной разработки

1. Не вносить изменения в `main` до отдельного тестирования и явного решения о выпуске.
2. Сохранить совместимость с существующей коллекцией Firestore `users/{uid}/notes`.
3. Существующие поля `title`, `body`, `folder`, `favorite`, `createdAt`, `updatedAt` не переименовывать и не удалять.
4. Новые поля добавлять постепенно и считать необязательными для старых записей.
5. Не менять Firestore Security Rules и Firebase Authentication без отдельной проверки.
6. Перед миграциями и релизом проверять экспорт/восстановление резервной копии.
7. Любая функция, требующая нативного разрешения (фото, уведомления, биометрия), должна иметь понятный запрос разрешения и безопасный fallback для веб-версии.
8. Каждый этап — отдельный коммит; после этапа проверять веб-сборку и Android APK.

## 3. Архитектура

- UI: текущие HTML/CSS/JavaScript-модули, с постепенным выделением экранов и компонентов.
- Native wrapper: Capacitor Android; веб-версия продолжает работать без нативных плагинов.
- Authentication: Firebase Anonymous Auth на первом этапе, текущий UID и пользовательские данные не сбрасывать.
- Database: Cloud Firestore, путь `users/{uid}/notes`.
- Media: Firebase Storage для изображений, с ограничением размера/типа и правилами доступа по UID.
- Local state/cache: Firestore IndexedDB persistence; не кэшировать сетевые запросы Firestore вручную через Service Worker.
- Native capabilities: Capacitor Local Notifications для напоминаний; биометрический плагин для Android после проверки совместимости; вебу — PIN/локальная блокировка как отдельный fallback, без обещания аппаратной биометрии.
- Backup: JSON-экспорт с версией схемы, импорт с предварительным просмотром и защитой от случайной перезаписи.

## 4. Модель данных (аддитивное расширение)

Текущие поля остаются без изменений. Предлагаемые новые необязательные поля заметки:

| Поле | Тип | Назначение |
|---|---|---|
| `tags` | `string[]` | Теги заметки |
| `pinned` | `boolean` | Закрепление |
| `color` | `string` | Необязательная цветовая метка из палитры |
| `attachments` | `array` | Метаданные файлов в Storage |
| `reminderAt` | timestamp/null | Время напоминания |
| `checklist` | `array` | Элементы чек-листа, если хранятся структурно |
| `archivedAt` | timestamp/null | Архивация без удаления |

Для коллекций можно добавить отдельную коллекцию `users/{uid}/collections` с полями `name`, `symbol`, `color`, `createdAt`, `updatedAt`. На переходном этапе строковое поле `folder` в заметках остаётся источником обратной совместимости; миграция на `collectionId` допускается только после теста и не является обязательной для первой итерации.

## 5. Этапы реализации

### Этап 0 — безопасная база
- Создать отдельную ветку от стабильного `main`.
- Зафиксировать концепцию, технические решения и модель данных.
- Проверить структуру текущего приложения и существующие Firebase-пути.
- Не менять рабочий сайт и production-данные.

### Этап 1 — дизайн-система и навигация
- CSS-токены: фон, поверхности, золото, текст, границы, радиусы, интервалы.
- Адаптивная нижняя навигация с safe-area отступами.
- Экраны-оболочки: Архив, Коллекции, Избранное, Настройки.
- Состояния загрузки, пустого архива и ошибок.
- Сохранить текущие операции создания, чтения, изменения и удаления заметок.

### Этап 2 — коллекции и теги
- Создание/переименование/удаление коллекций.
- Фильтрация заметок по коллекции и тегам.
- Избранное и закрепление.
- Старые заметки без новых полей продолжают отображаться.

### Этап 3 — редактор GRIMOIRE
- Безопасное форматирование текста, заголовки, цитаты и списки.
- Чек-листы с доступным управлением.
- Ссылки и вставка изображений.
- Автосохранение с индикатором состояния.
- Санитизация HTML с allowlist, включающим только необходимые элементы и безопасные атрибуты.

### Этап 4 — медиа и резервные копии
- Загрузка изображений в Firebase Storage по UID.
- Проверка MIME-типа и размера, индикатор прогресса.
- JSON-экспорт с `schemaVersion`.
- Импорт с предварительным просмотром, проверкой формата и подтверждением конфликтов.

### Этап 5 — хроника и напоминания
- Календарный экран по датам создания/изменения и напоминаниям.
- Локальные уведомления Android через Capacitor.
- Запрос разрешения на уведомления в нужный момент.
- Отмена/перепланирование уведомлений при изменении заметки.
- В веб-версии — совместимый интерфейс без обещания фоновых уведомлений.

### Этап 6 — защита
- Биометрическая разблокировка через нативный плагин, если устройство поддерживает её.
- PIN как резервный способ; безопасное хранение секрета через платформенное хранилище, не в открытом localStorage.
- Автоматическая блокировка по таймауту.
- Чётко отделить блокировку интерфейса от сквозного шифрования: биометрия сама по себе не шифрует Firestore-данные.

### Этап 7 — проверка и релиз
- Проверка существующих данных и синхронизации двух клиентов.
- Проверка офлайн-чтения и последующей синхронизации.
- Проверка разрешений, уведомлений, изображений и резервного восстановления.
- Тестирование на разных размерах Android-экранов.
- Подготовка подписанного release AAB, политики конфиденциальности, описания и графики Google Play.

## 6. Критерии готовности

- Все старые заметки открываются без ручной миграции.
- Создание/редактирование/удаление и избранное работают как прежде.
- Нижняя навигация не перекрывает контент и учитывает системные safe areas.
- Новые поля не ломают старые документы Firestore.
- Экспорт и импорт проверены на тестовой копии.
- Уведомления и биометрия корректно обрабатывают отказ в разрешении/отсутствие поддержки.
- Основная ветка `main` остаётся неизменной до одобрения релиза.
